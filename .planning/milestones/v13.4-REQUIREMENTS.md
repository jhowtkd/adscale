# Requirements: ADScale v13.4 Fechamento de Evidência Operacional

**Defined:** 2026-06-25
**Milestone:** v13.4 Fechamento de Evidência Operacional
**Core Value:** Users can go from a single base creative and a brief to multiple platform-ready ad variations in minutes, with full creative control and review.

## Scope

Fechar o tech debt operacional deixado pela v13.3: sair de `fixtureOnly: true` e `operationalEvidence: insufficient_sample` para amostra real por `clientProfileId`, smoke owner com dado live, e release gate honesto que só libera claims quando a suficiência passar.

**Starting point:** v13.3 entregou infraestrutura cliente-agnóstica com gate técnico verde (`technicalRegression: pass`) e evidência operacional honestamente insuficiente. O caminho genérico de promoção/import com `sourceLabel` já existe; falta volume e prova live.

**In scope:** corpus `real_customer` para pelo menos um perfil não-fixture, atualização de `activeBrandSample`, execução do `172-RELEASE-CHECKLIST.md`, captura em `172-EVIDENCE.json`, rerodar release gate, política de unlock de claims.

**Out of scope:** novos eixos criativos, integrações de distribuição, dashboard multi-marca profundo, automação de fila de incerteza, aprovação manual de regras, marketing copy a partir de `conceituacao.md`.

**Closure note:** Infrastructure shipped and unit-tested (`passed_with_tech_debt`). Live operational pass remains blocked until `npm run db:migrate` + `npm run seed:live-real-customer-corpus -- --confirm` on owner workspace.

## Requirements

### Live Real-Customer Corpus (LIVE)

- [ ] **LIVE-01**: Owner can promote or import corpus rows with `real_customer` sourceLabel for at least one non-fixture `clientProfileId` through the generic v13.3 path (no customer-specific scripts). _Infrastructure: `seed-live-real-customer-corpus.ts` ships; live `--confirm` not executed._
- [ ] **LIVE-02**: Active evidence scope for the selected profile includes `real_customer` rows with honest source composition counts. _Infrastructure: `refresh-v13-3-operational-evidence.ts` wired; needs `173-CORPUS-MANIFEST.json` from live seed._
- [x] **LIVE-03**: Corpus and evidence surfaces continue to distinguish `synthetic_fixture`, `operator_imported`, and `real_customer` without framing Cenbrap as product proof.

### Sample Sufficiency and Claim Honesty (SAMPLE)

- [x] **SAMPLE-01**: `activeBrandSample.fixtureOnly` becomes `false` when the selected profile meets non-fixture `real_customer` sample sufficiency per existing rules. _Logic implemented and tested; live state still `fixtureOnly: true` until seed runs._
- [x] **SAMPLE-02**: Customer-real, agreement-rate, and quality-improvement claims remain withheld until sample and source sufficiency pass for the selected profile.
- [x] **SAMPLE-03**: Fixture-only evidence alone cannot unlock customer-real claims, even when other operational smoke items pass.

### Owner Smoke and Manual UAT (SMOKE)

- [ ] **SMOKE-01**: Owner completes `172-RELEASE-CHECKLIST.md` factual-alert, evidence-link, and proposal-separation items with live workspace data. _Automated panel tests pass; live browser checklist pending._
- [ ] **SMOKE-02**: Owner verifies settings persistence (profile + workspace save, hard refresh) per checklist and records pass/fail honestly. _Route tests pass; live hard-refresh UAT pending._
- [x] **SMOKE-03**: Smoke outcomes are captured in a structured operational evidence record scoped to the active workspace/profile.

### Release Evidence and Claim Unlock (EVIDENCE)

- [ ] **EVIDENCE-01**: `172-EVIDENCE.json` (archived path under `milestones/v13.3-phases/`) is updated to reflect live corpus composition and smoke results for the active brand sample. _Refresh path wired; file still `insufficient_sample` without live manifest._
- [ ] **EVIDENCE-02**: Release gate (`npm run v13-3-release-gate` or v13.4 successor) reports `operationalEvidence` beyond `insufficient_sample` when live corpus and smoke criteria are met. _Auto-refresh on manifest exists; blocked until live seed._
- [x] **EVIDENCE-03**: Customer-real claim unlock applies only when both technical regression and operational evidence pass for the selected brand — no manual override without recorded evidence.
