<objective>
Remove the one-client-per-workspace assumption from the database and profile-dependent server paths so a workspace can safely operate multiple client profiles without cross-client brand data leakage.
</objective>

<must_haves>
- Multiple `client_profiles` rows can share one `workspace_id` after migrations run.
- Existing campaigns resolve client profile deterministically: explicit id, exact client-name match, sole-profile fallback, then `null` on ambiguity.
- Brand-kit writes and deletes never mutate an arbitrary profile when a workspace has more than one profile.
- Brand memory retrieval/projection is scoped by `clientProfileId` or an equivalent profile-specific scope.
- References, voice config, corpus, and calibration rules retain `clientProfileId` isolation.
- Targeted regression tests prove no cross-client leakage.
</must_haves>
