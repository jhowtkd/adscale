# Requirements: ADScale v13.0 Brand Taste Calibration Loop

**Defined:** 2026-06-20
**Milestone:** v13.0 Brand Taste Calibration Loop
**Core Value:** Users can go from a single base creative and a brief to multiple platform-ready ad variations in minutes, with full creative control and review.

## Scope

Transformar julgamento humano em calibracao reutilizavel: decisoes esparsas do Jhonatan deixam de ser trabalho operacional recorrente e viram sinais estruturados, perfis de gosto por marca, regras aprovaveis, aplicacao em advisor/geracao e fila de incerteza.

**Starting point:** v12.9 fechou como `tech_debt`: o workflow de decisao e a amostra de 5 rows revisaveis existem, mas `humanDecisionCount=0`, `additionalNeeded=5`, `agreementRate=null`, e as rows Cenbrap sao `synthetic_fixture`.

**In scope:** modelo canonico de sinais de julgamento, perfil de gosto por marca, extracao de regras calibraveis, aplicacao no advisor/prompt-builder, fila de incerteza e release gate de evidencia/calibracao.

**Out of scope:** fine-tuning, claims comerciais de qualidade, multi-tenant voice management completo, dashboard amplo de analytics, performance/media blending e substituicao do pipeline de imagem.

## Requirements

### Calibration Signal Model (SIGNAL)

- [x] **SIGNAL-01**: System records each human decision as a calibration event linked to output, brand/client, campaign context, system verdict, human verdict and source label.
- [x] **SIGNAL-02**: Calibration events persist reviewer, reviewedAt, decision, mismatch bucket and sanitized note without prompts, signed URLs or secrets.
- [x] **SIGNAL-03**: Repeated imports or recorder runs are idempotent and do not duplicate calibration events.
- [x] **SIGNAL-04**: Existing Cenbrap decision capture can write to or adapt into the calibration signal model.

### Brand Taste Profile (PROFILE)

- [x] **PROFILE-01**: System builds an inspectable brand taste profile from calibration events for a client/brand.
- [x] **PROFILE-02**: Profile separates positive patterns, rejection patterns and `quase` patterns.
- [x] **PROFILE-03**: Profile exposes evidence level: `uncalibrated`, `seed_calibrated`, `assisted` or `evidence_backed`.
- [x] **PROFILE-04**: Profile reports source composition so fixture-only learning cannot be represented as customer-real validation.

### Calibration Rule Extraction (RULE)

- [x] **RULE-01**: System groups system-human mismatches into actionable rule candidates.
- [x] **RULE-02**: Rule candidates state category, rationale, supporting decisions, confidence and evidence caveats.
- [x] **RULE-03**: Jhonatan can approve, reject or deprecate extracted rules before they affect generation or advisor behavior.
- [x] **RULE-04**: Rules cannot be promoted from ambiguous or single-row evidence without explicit caveat.

### Advisor and Generation Application (APPLY)

- [x] **APPLY-01**: Advisor/preflight evaluates outputs using global Olhar plus approved brand taste rules.
- [x] **APPLY-02**: Prompt-builder can retrieve approved brand rules and include them as bounded taste constraints.
- [x] **APPLY-03**: Verdict explanations reference applied rule ids instead of vague taste claims.
- [x] **APPLY-04**: Applying taste rules preserves factual/export safety regression coverage.

### Uncertainty Queue (QUEUE)

- [x] **QUEUE-01**: System computes or classifies judgment uncertainty from sample level, disagreement history, source evidence and rule conflicts.
- [x] **QUEUE-02**: Low-confidence outputs route to human review with a reason explaining what the decision will teach.
- [x] **QUEUE-03**: High-confidence calibrated outputs do not require human review by default.
- [x] **QUEUE-04**: Batch review supports 5 to 15 decision items without turning human review into permanent throughput.

### Calibration Evidence and Claims (EVIDENCE)

- [x] **EVIDENCE-01**: Release evidence reports agreement, uncertainty reduction and mismatch trends by brand/profile.
- [x] **EVIDENCE-02**: Claims matrix blocks agreement, quality or customer-real claims unless sample and source evidence support them.
- [x] **EVIDENCE-03**: System can compare behavior before and after approved rules on a new Cenbrap batch or evaluation set.
- [x] **EVIDENCE-04**: Milestone audit states what is calibrated, what remains uncertain and what still depends on Jhonatan.

## Future Requirements

### Multi-Client Scale (deferred)

- **MULTI-01**: Client voice documents can be managed per client profile through a dedicated UI.
- **MULTI-02**: Taste profiles can be compared across clients without leaking one client's rules into another.

### Performance Blending (deferred)

- **PERFLOOK-01**: Creative verdicts can be compared with CTR/CPA/ROAS once both quality and performance samples are sufficient.
- **PERFLOOK-02**: Recommendations can balance art-direction quality and media outcome without weakening export compliance.

## Out of Scope

| Feature | Reason |
| --- | --- |
| Fine-tuning model/rubric | Premature; rule/event loop must prove value first |
| Broad taste dashboard | Start with inspectable profile and evidence artifacts |
| Multi-client voice UI | Generalize after Cenbrap proves the loop |
| Commercial quality claims | Blocked until sufficient human and source evidence |
| Performance/media blending | Separate evidence problem |
| Image-generation model changes | This milestone changes judgment/calibration, not generation provider |
