Output: target-aware format sizing helper, derivation job wiring, stronger prompt/test coverage, and a clean build/test baseline for Plan 44-02.
</objective>

<task type="auto">
  <name>Task 1: Add target-aspect generation sizing</name>
  <files>app/src/lib/formats.ts, app/src/lib/formats.test.ts</files>
  <action>
    Replace or extend `formatToOpenAISize` with a helper that separates final output dimensions from generation request size.

    Required behavior:
    - Keep `getTargetDimensions(formatId, isPreview)` as the source of final stored dimensions.
    - Add a model-aware generation-size helper, for example `formatToOpenAIImageSize(formatId, options)`.
    - For configured GPT Image 2 models (`gpt-image-2` and dated variants), prefer target-aspect generation sizes:
      - `1:1` -> `1024x1024`
      - `4:5` -> `1024x1280`
      - `9:16` -> `1152x2048`
    - For non-flexible or unknown image models, use an explicit fallback to the supported SDK sizes and make that fallback observable in the helper/test names. Do not silently force square for 4:5 or 9:16.
    - Preview mode for `format_adaptation` must keep target aspect. Do not return `1024x1024` for 4:5 or 9:16 format adaptation previews.
    - Keep any OpenAI SDK type cast isolated in this helper if the SDK type does not expose flexible `gpt-image-2` sizes. Do not spread casts into `derivation.ts`.

    Add `app/src/lib/formats.test.ts` if missing. Cover:
    - 4:5 returns a 4:5 generation size for GPT Image 2.
    - 9:16 returns a 9:16 generation size for GPT Image 2.
    - Preview mode does not collapse format adaptation to square.
    - Unknown formats still safely fall back to square.
  </action>
  <verify>cd app && npm test -- src/lib/formats.test.ts</verify>
  <done>
    Format sizing tests fail if 4:5 or 9:16 generation requests are square, or if preview mode forces square output for format adaptation.
  </done>
</task>
