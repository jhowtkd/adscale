# Plan 98-01: Past-Due Policy and Recovery

## Objective

Define one explicit past-due spend policy, enforce it in server gates, and provide a direct payment recovery path.

## Must Haves

- The chosen policy is documented next to billing behavior and reflected in API responses.
- `past_due` is not collapsed into generic no-access messaging.
- Spend gates apply the same policy across preview, batch, preflight, and assisted generation paths.
- Customer Portal recovery works for the current workspace.

## Tasks

### Task 1: Lock the policy

Document the decision for remaining credits during `past_due`, then encode it in `server/billing/access.ts`, `credits.ts`, and `gates.ts` without affecting beta entitlements.

### Task 2: Expose recovery state

Return actionable past-due metadata from billing status and wire the existing portal mutation into the relevant Billing UI state.

### Task 3: Cover failure and recovery

Extend Stripe event, access, gate, portal route, hook, and BillingTab tests for `invoice.payment_failed` and portal recovery.

## Verification

- Focused billing event/access/gate/portal tests pass.
- A `past_due` fixture receives the documented spend result and a visible portal action.
