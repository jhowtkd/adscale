# Phase 206 — UI Design Contract

> Visual and interaction contract for version comparison and approval. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn, existing project installation |
| Preset | `b2fA` (`base-nova`, neutral theme, subtle menu accent) |
| Component library | Base UI through existing shadcn primitives |
| Icon library | Lucide |
| Font | Inter for interface copy; Space Mono only for compact version/status labels already using the mono treatment |

Reuse the existing `Dialog`, `Select`, `Button`, `Badge`/`StatusBadge`, `Skeleton`, and tooltip primitives. Do not add a comparison package, image-viewer package, or second modal system. The compare workspace is a phase-specific composition over the existing dialog primitive.

---

## Spacing Scale

Declared values (existing tokens, all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon gaps, timeline connector offsets |
| `--space-2` | 8px | Compact controls, badge and metadata gaps; compact row vertical padding |
| `--space-4` | 16px | Compact row horizontal padding; default panel, card, and mobile gutter |
| `--space-5` | 24px | Diff group and comparison section gaps |
| `--space-6` | 32px | Desktop compare workspace inset and column gap |
| `--space-7` | 48px | Major section separation only |

Exceptions: icon-only controls retain the existing 32px desktop size but must use `--control-touch` (44px) on coarse-pointer/mobile surfaces. The full-screen mobile compare workspace uses safe-area padding in addition to the scale.

## Typography

Use exactly these four sizes and two weights across this phase:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Metadata / label | 12px (`--text-caption`) | 500 | 1.4 |
| Body | 14px (`--text-body`) | 400 | 1.5 |
| Section heading | 16px (`--text-section`) | 500 | 1.3 |
| Workspace heading | 20px (`--text-page`) | 500 | 1.2 |

Version labels may use Space Mono at 12px/500. All other copy uses Inter. Do not introduce bold weight; hierarchy comes from size, spacing, surface, and the existing status treatment.

## Color

Color must use the existing semantic tokens so light and dark themes remain equivalent.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surface-base` (light `oklch(0.992 0.004 145)` / dark `oklch(0.18 0.009 145)`) | Compare workspace, timeline background, primary reading surface |
| Secondary (30%) | `--surface-raised` (light `oklch(0.955 0.007 145)` / dark `oklch(0.22 0.01 145)`) | Version rows, diff blocks, metadata panels, image stage |
| Accent (10%) | `--accent-primary` (light `oklch(0.62 0.21 145)` / dark `oklch(0.78 0.22 145)`) | Selected-version marker, primary approval CTA, synchronized-view active indicator, focus ring |
| Destructive | `--danger-text` plus `--danger-bg` | Ineligible/error state and preview failure only; promotion itself is not destructive |
| Warning | `--warning-text` plus `--warning-bg` | Stale/superseded/CAS conflict and proposals that will become stale |

Accent reserved for: the active two-version selection, the primary “make official” action, the active synchronized zoom/pan state, and keyboard focus. Additions/removals/moves must also include explicit text labels and icons; color alone never communicates a diff.

## Information Architecture

### Persistent history in assistant context

- Add **Histórico de versões** to `AssistantContextPanel`, below readiness and above job status. It remains visible in the 320px desktop context rail and in the existing mobile **Contexto** tab.
- Group lineages by artifact with a compact selector when more than one plan or creative lineage exists. Never mix versions from different lineages in one timeline or comparison selection.
- Render a linear vertical timeline, newest first. Each row contains `v{n}`, one or more plain-language state labels (**Oficial**, **Em trabalho**, **Oficial anteriormente**), creation date/time, origin, and a one-line triggering-feedback summary. Internal IDs and technical provenance are absent.
- The official version is identified by label and icon, not accent color alone. The working version uses a separate neutral label when it is not official.
- Each eligible row exposes **Comparar com a oficial**. Opening it compares the official current version with that row. When official and working differ, the section-level **Comparar oficial e versão em trabalho** shortcut opens with that pair preselected. When only one distinct version exists, keep the shortcut disabled and explain “Crie ou selecione outra versão para comparar.”
- Chat action cards that created a version expose a secondary **Ver no histórico** link and, when a distinct official version exists, **Comparar com a oficial**.

### Wide comparison workspace

- Open comparison as a modal workspace over chat using the existing `Dialog` focus trap and overlay. On desktop it uses `min(100dvw - 32px, --content-wide)` width and `calc(100dvh - 32px)` height. On mobile it is full viewport with safe-area padding and no rounded bottom edge.
- Header is persistent and contains: **Comparar versões do plano** or **Comparar versões do criativo**, artifact/lineage name, two labeled version selectors (**Versão A**, **Versão B**), status/date/feedback for each version, and an icon control named **Fechar comparação**. Selector options are restricted server-side and client-side to the open lineage; selecting the same version in both slots is invalid.
- The compare body/content is the workspace focal point: it receives the largest surface area, first content focus after the header, and the strongest reading hierarchy. It owns scrolling; selectors and footer support this focal content rather than competing with it.
- Footer is persistent and contains eligibility explanation, secondary **Fechar comparação**, and the promotion CTA as the primary action anchor: rightmost on desktop, full-width and last in reading order on mobile, using the reserved accent treatment. Closing restores the trigger focus and the exact chat scroll position from before opening.
- Comparison is read-only until the user activates the footer action. Changing selectors, filters, zoom, pan, or opening/closing the workspace never changes approved or working pointers.

## Comparison Contracts

### Plan comparison

- Default to **Somente alterações**. A labeled switch **Mostrar campos sem alteração** reveals unchanged fields without changing the selected versions.
- Preserve canonical order: **Estratégia → Ângulos → Ganchos → CTAs → Restrições**.
- Each changed field is a bordered diff block with an explicit change label: **Adicionado**, **Removido**, **Editado**, or **Movido**. List item numbering remains visible so reordering of angles, hooks, and CTAs is understandable.
- Desktop (`>= 768px`): two equal columns, **Antes — v{A}** and **Depois — v{B}**. Mobile: stack **Antes** then **Depois** within each field; persistent subheaders keep version identity visible while scrolling.
- Empty result copy: **“Estas versões não têm diferenças nos campos do plano.”** The unchanged-fields control remains available.

### Creative comparison

- Desktop (`>= 768px`): two equal preview columns. Mobile: stack Version A then Version B. Persistent headers identify `v{n}` and state on every viewport.
- Start with the complete image fitted (`object-contain`) against `--surface-inset`. Keep aspect ratio and never crop by default.
- One shared toolbar provides **Reduzir**, zoom percentage, **Ampliar**, **Ajustar**, and **Redefinir posição**. Wheel/pinch zoom and drag/pan update both previews to the same normalized zoom and focal point. Keyboard users can operate toolbar controls and pan the focused stage with arrow keys. Respect reduced motion.
- Beneath previews, show safe decision metadata only: version/state, format and dimensions, bound plan version, CTA, date, and triggering feedback. Do not show UUIDs, output keys, provider data, prompts, or signed URLs.
- Change copy is headed **Mudanças pretendidas** and prefaced by **“Com base no pedido desta revisão:”**. It may use persisted feedback and intended changes only; never claim detected or pixel-level differences.
- If one preview fails, retain its stage dimensions, header, and metadata. Show **“Não foi possível carregar esta prévia.”** with **Tentar novamente**. The other preview remains usable; promotion eligibility is shown independently from preview availability.

## Approval and Promotion Contract

- Footer CTA is **Aprovar v{n}** for a ready version and **Promover v{n}** for a previously approved/older eligible version. If the selected target is already official, disable the CTA and state **“v{n} já é a versão oficial.”**
- Pending, running, failed, canceled, invalid, stale/superseded, cross-lineage, and cross-scope targets never expose an enabled CTA. Show the specific eligibility reason adjacent to the disabled control.
- Activation opens an existing-style `Dialog` confirmation; use the default primary button, not destructive styling. The dialog names the transition **v{current} → v{target}**, lists canonical writes, lists proposal(s) that will become stale, and states **“Esta ação não usa créditos e não exclui nenhuma versão.”**
- Confirmation buttons: **Voltar à comparação** and **Tornar v{target} oficial**. While pending, disable dismissal and both actions, set `aria-busy`, and label the primary action **Atualizando versão oficial…**.
- A creative target generated from a non-current plan requires a reviewed linked-plan comparison. Show a blocking callout with **Comparar plano v{linked} com v{current}**. After that server-verifiable comparison is completed, mark **Plano comparado** with date/time; only then enable compound confirmation.
- Compound confirmation names both transitions separately under **Plano** and **Criativo**, repeats the no-credit/no-deletion statement, and uses one CTA: **Tornar plano e criativo oficiais**. Partial success must never be represented.
- On success, keep the compare workspace open long enough to announce via live region **“v{target} agora é a versão oficial.”**, refresh both timeline and headers, mark the prior official as **Oficial anteriormente**, and set the promoted version as both **Oficial** and **Em trabalho**.

### Conflict recovery

- On stale revision/CAS conflict, keep the workspace open and replace the footer action area with a persistent warning callout: **“A versão oficial mudou enquanto você comparava.”**
- Show **“Antes: v{old}. Agora: v{new}.”** and **Revisar estado atualizado**. Refresh canonical state, preserve the selected target only if still eligible and in-lineage, invalidate any prior confirmation/linked-plan acknowledgement, and require the user to review and confirm again.
- Never auto-retry, silently close, or show success on conflict. Move focus to the warning heading and announce it through `role="alert"`.

## Responsive and Accessibility Contract

- Breakpoint follows the existing assistant shell: desktop comparison columns at `md` (768px); stacked layout below it.
- Maintain a single logical reading order: header → selectors → comparison → metadata → eligibility → actions. Visual two-column layout must not interleave screen-reader output.
- Version selectors have visible labels and announce version, state, and date. Timeline selection uses native buttons/controls with `aria-pressed` where applicable; maximum-two behavior is explained in text, not only by disabling options.
- Diff type is always present as visible text. Preview toolbar controls have Portuguese accessible names and 44px touch targets. Image alt text follows **“Prévia do criativo v{n}, {format}”** without inventing visual content.
- Modal open traps focus; Escape closes only when no mutation is pending; close returns focus to the exact history/chat trigger and restores chat scroll. Sticky headers must not obscure focused elements.
- Loading uses existing `Skeleton` shapes for timeline rows, headers, diff blocks, and preview stages. Keep the layout dimensions stable to avoid selection or image-stage shifts.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Ready target: **Aprovar v{n}**. Older eligible target: **Promover v{n}**. Confirmation: **Tornar v{n} oficial** |
| Empty history heading | **Ainda não há versões para comparar** |
| Empty history body | **As revisões confirmadas aparecerão aqui com origem, estado e histórico.** |
| Missing pair | **Selecione duas versões da mesma linha para comparar.** |
| Plan no-change state | **Estas versões não têm diferenças nos campos do plano.** |
| Preview error | **Não foi possível carregar esta prévia. Tente novamente.** |
| Generic compare error | **Não foi possível comparar estas versões. Atualize o histórico e tente novamente.** |
| Ineligible target | **Esta versão não pode se tornar oficial porque está {estado}. Escolha uma versão pronta ou aprovada anteriormente.** |
| Confirmation | **Tornar v{target} oficial?** — **A versão oficial muda de v{current} para v{target}. Esta ação não usa créditos e não exclui nenhuma versão.** |
| Confirmation secondary action | **Voltar à comparação** |
| Compound confirmation | **Tornar plano e criativo oficiais?** — name both transitions and state **Esta ação é única: ou as duas versões mudam, ou nenhuma muda.** |
| Conflict | **A versão oficial mudou enquanto você comparava. Revise o estado atualizado antes de confirmar novamente.** |
| Destructive confirmation | None. This phase does not delete history; approval/promotion uses default confirmation styling. |

Use “versão oficial” in user copy. Reserve “approved current”, “working pointer”, “CAS”, “lineage”, and internal statuses for code/telemetry, not the primary surface.

## State Matrix

| State | Visual contract | Available action |
|-------|-----------------|------------------|
| Loading | Stable skeletons matching final timeline/compare geometry | None |
| One version only | Official row plus empty-pair guidance | **Comparar oficial e versão em trabalho** disabled |
| Two valid versions | Selected markers and populated comparison | **Comparar versões selecionadas**; approve/promote if eligible |
| Same version in A/B | Inline selector error | Promotion disabled |
| Ready target | Neutral eligibility copy | **Aprovar v{n}** |
| Previously approved/older target | Explain preserved descendants/history | **Promover v{n}** |
| Already official | Official label | Disabled with reason |
| Pending/running/failed/canceled/invalid | Semantic status and explicit reason | Disabled |
| Linked plan not reviewed | Warning callout naming linked/current plans | **Comparar plano…** only |
| Mutation pending | Busy label, controls locked | No dismissal/repeat |
| Conflict | Persistent warning with old/new official versions | **Revisar estado atualizado** |
| Success | Refreshed official/working labels and live announcement | No duplicate action |
| Preview failure | Error placeholder; metadata retained | **Tentar novamente**; promotion governed separately |
