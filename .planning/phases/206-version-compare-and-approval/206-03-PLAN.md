<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| thread API to client mapper | Server JSON must be parsed without exposing internal fields or trusting malformed dates/status. |
| history UI to compare/promote hooks | Browser-selected lineage/version/revision values remain untrusted hints; server authority is mandatory. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-206-14 | Elevation of privilege | IDOR / scope checks in history selection | mitigate | Build options only from one server-returned lineage and still rely on server scope/lineage validation. |
| T-206-15 | Tampering | stale CAS in promotion mutation | mitigate | Send explicit expected revisions and acknowledgement IDs; disable automatic mutation retry on 409. |
| T-206-16 | Information disclosure | timeline/thread mapper | mitigate | Render only bounded presentation labels/feedback; never surface UUIDs, output keys, prompts, provider data, or signed URLs. |
| T-206-17 | Spoofing | forged comparison acknowledgement | mitigate | Hook calls the server-verifying acknowledgement route; no local boolean counts as review proof. |
| T-206-18 | Tampering | atomic compound rollback | mitigate | UI treats promotion as one command and never represents partial success; Plan 02 transaction remains authoritative. |
| T-206-19 | Tampering | unsafe status promotion | mitigate | Disabled UI reasons follow server eligibility, but unknown statuses remain disabled and server allowlist decides. |
| T-206-SC | Tampering | package supply chain | mitigate | Use installed TanStack Query and assistant UI primitives; no package install. |
</threat_model>
