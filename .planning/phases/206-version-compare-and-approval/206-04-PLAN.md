<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| comparison DTO to DOM | Safe server presentation is rendered; raw snapshots/technical IDs must not leak through debug or fallback UI. |
| browser confirmation to promotion API | Selection, status, revision, and acknowledgement remain untrusted and can become stale while modal is open. |
| preview URL to image element | Ephemeral signed capability must stay in-memory/response-only and out of local persistence/logging. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-206-20 | Elevation of privilege | IDOR / scope checks in dialog selectors/card shortcuts | mitigate | Populate from scoped presentations and rely on server same-lineage/four-scope checks for every request. |
| T-206-21 | Spoofing | forged comparison acknowledgement | mitigate | Enable compound confirmation only from server-issued revision-bound acknowledgement, never local state alone. |
| T-206-22 | Tampering | stale CAS conflict | mitigate | Disable automatic retries, clear confirmation/receipt on 409, refresh state, and require fresh explicit confirmation. |
| T-206-23 | Tampering | atomic compound rollback | mitigate | Submit one compound command and render only full success or full conflict/failure; never synthesize partial success. |
| T-206-24 | Tampering | unsafe status promotion | mitigate | Default unknown/ineligible states to disabled and show server-provided reason; server allowlist remains authoritative. |
| T-206-25 | Information disclosure | creative preview/metadata UI | mitigate | Render positive allowlist fields; do not show/log UUIDs, output keys, prompts, provider data, or persist signed URLs. |
| T-206-SC | Tampering | package supply chain | mitigate | Reuse installed Dialog, Select, Button, Skeleton, Lucide, and native pointer/keyboard behavior; no installs. |
</threat_model>
