<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to compare route | Untrusted lineage/version IDs and include-unchanged flag enter authenticated server code. |
| repository to comparison presenter | Internal snapshots may contain storage/provenance identifiers that must not cross into the primary UI DTO. |
| object storage to response | Short-lived signed URLs are response-only capabilities and must never enter persistence or logs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-206-01 | Elevation of privilege | IDOR / scope checks in compare route/service | mitigate | Derive all four scope dimensions from the authenticated thread and require both versions to match the requested lineage. |
| T-206-02 | Tampering | comparison selection | mitigate | Reject identical IDs, mixed lineages, and unknown versions; comparison performs no head/status writes. |
| T-206-03 | Information disclosure | creative presenter | mitigate | Build a positive allowlist DTO; resolve signed URLs at read time and exclude output keys, prompts, provider payloads, and technical provenance. |
| T-206-04 | Spoofing | forged comparison acknowledgement | mitigate | This read-only plan creates no acknowledgement; Plan 02 persists a scoped revision-bound receipt rather than trusting a browser flag. |
| T-206-05 | Tampering | stale CAS / unsafe status promotion | mitigate | Comparison returns canonical head revision/status for review; all mutation enforcement remains server-owned in Plan 02. |
| T-206-06 | Tampering | atomic compound rollback | mitigate | No compound mutation occurs here; Plan 02 owns one transaction and rollback tests before any UI enables promotion. |
| T-206-SC | Tampering | package supply chain | mitigate | No package install is allowed; use existing Zod, storage, format, and route primitives. |
</threat_model>
