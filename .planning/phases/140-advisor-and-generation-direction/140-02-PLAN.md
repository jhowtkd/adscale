# Plan 140-02: Generation Direction Injection and Score Demotion

## Purpose

Make generation prompts act on the new `Olhar` instead of merely judging after the fact. Then demote numeric score to analytics/detail while keeping it available for existing code.

## Scope

In scope:

- Add generation direction builder.
- Inject direction into `prompt-builder.ts` after hard rules and before flexible creative strategy.
- Wire client voice resolver conservatively.
- Demote score in server contracts/types without breaking existing UI.

Out of scope:

- Full review surface redesign.
- Human decision language (`Entra`, `Quase`, `Nao entra`) UI.
- Override reason UX.

## Tasks

### 140-02-01: Inject generation direction into prompt-builder

Implement `buildGenerationDirectionSection()` with:

- dominant idea / gestalt to preserve.
- sacred facts from canonical creative, CTA, offer, product, client and export constraints.
- allowed variation range based on generation mode and creative level.
- anti-patterns from global Olhar.
- optional client voice section only when approved or explicitly safe.

Acceptance:

- Prompt contains `DIRECAO DE ARTE PARA GERACAO` or equivalent stable header.
- Direction section appears after non-negotiable hard rules and before flexible strategy/feedback.
- Existing CTA/factual hard rules still appear before creative strategy and memory blocks.
- If Cenbrap voice review is `pending_review`, tests prove no unapproved voice override is injected by default.

Automated:

`cd app && npm test -- src/server/ai/olhar/generation-direction.test.ts src/server/ai/prompt-builder.test.ts`

### 140-02-02: Demote numeric score to compatibility/detail

Update score prompt and related types so:

- score prompt asks for direction-first output and treats `qualityScore` as secondary.
- `qualityScore` stays stored for analytics/backward compatibility.
- primary response/server contract exposes or preserves `olharVerdict`, `whatWorks`, `whatBlocks`, `directionNote` where Phase 139 payload exists.
- frontend-facing types can carry `olharVerdict`/`exportStatus` without forcing Phase 141 UI work.

Acceptance:

- Tests assert score prompt says numeric score is secondary/internal.
- Existing score normalization still accepts old responses.
- Derivation hook/mock types include `olharVerdict` and `exportStatus`.
- No UI redesign required in this phase.

Automated:

`cd app && npm test -- src/server/ai/creative-score.test.ts src/lib/hooks/use-derivations.test.tsx`
