# Plan 140-01: Leitura do Base and Passagem Olhar

## Purpose

Change the advisor's judgment language before touching UI: preflight becomes a creative reading of the base, and final QA becomes `Passagem Olhar` layered over the existing export/gate checks.

## Scope

In scope:

- Add base creative reading contract.
- Update preflight prompt/normalization while preserving existing compatibility fields.
- Add Olhar QA helper that builds `OlharVerdictPayload` from QA/gate evidence.
- Update QA prompt language to distinguish `Olhar` from `Exportacao`.

Out of scope:

- Workspace UI redesign.
- Override UX.
- Active Cenbrap voice injection into generation prompts.

Create:

- `app/src/server/ai/olhar/base-reading.ts`

- `app/src/server/ai/olhar/olhar-qa.test.ts`

Modify:

- `app/src/server/ai/creative-qa.test.ts`

## Tasks

### 140-01-01: Add BaseCreativeReading and reframe preflight

Implement `BaseCreativeReading` with:

- `dominantIdea`
- `gestaltRead`
- `inviteWeight`
- `thumbnailRead`
- `brandPresence`
- `risks` capped at 2

Update preflight so it asks for `Leitura do base` and normalizes this object. Keep existing score fields for compatibility.

Acceptance:

- Prompt includes `Leitura do base`.
- Prompt asks for dominant idea, gestalt, invite, thumbnail read and brand presence.
- Normalizer caps risks at 2.
- Existing preflight consumers keep working.

Automated:

`cd app && npm test -- src/server/ai/olhar/base-reading.test.ts`

### 140-01-02: Add Passagem Olhar QA helper

Implement `olhar-qa.ts` that:

- builds/normalizes an `OlharVerdictPayload` using Phase 139 contracts.
- maps visual hard failures into `sem_opiniao`/`confusa`.
- creates short `whatWorks`, `whatBlocks`, and `directionNote`.
- never uses export-only failures as art-direction verdicts.

Update `creative-qa.ts` prompt to explicitly say `Passagem Olhar` and separate it from `Exportacao`.

Acceptance:

- QA prompt names `Passagem Olhar`.
- QA prompt does not collapse CTA/brand/format export failures into art-direction opinion.
- Helper returns valid `OlharVerdictPayload` or null conservatively.
- QA route can pass computed Olhar verdict data to repository helpers if available without breaking legacy response shape.

Automated:

`cd app && npm test -- src/server/ai/olhar/olhar-qa.test.ts src/server/ai/creative-qa.test.ts`
