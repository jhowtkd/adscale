**Update buildHardRulesSection** — currently receives `ctaText` and `isArtVariation` bool. Add `ctaSemantics?: CtaSemantics` from the contract when present. Apply these rules:
- If `ctaSemantics?.kind === "explicit"` → existing behavior: "The exact CTA, if present, must remain: {text}. Do not invent a new CTA."
- If `ctaSemantics?.kind === "inherited"` OR `ctaSemantics` is absent but mode is art_variation → "Use the original CTA from the reference creative. Do not add a different CTA or remove the existing CTA."
- For format_adaptation with `inherited` → "Preserve the CTA exactly as it appears in the source creative."
- For restyling with `inherited` → "The base image contains the factual CTA that must be preserved. Apply style language from the style reference only; do not replace the CTA with text from the style reference."
- `absent` kind: not yet surfaced in v11.1; treat same as no-CTA.

Keep backward compat: if `contract` is null/undefined, fall through to existing ctaText-based logic so no callers break.

**Add restyling factual-source instruction** in `buildDerivationPrompt` — after the existing hard rules section, when `config.generationMode === "restyling"` AND `config.contract?.styleAssetId` is not null, append to the prompt:
```
RESTYLING FACTUAL-SOURCE RULE:
The base image is the ONLY source of factual content (brand name, product name, offer, CTA, price, course name, logo). The style reference provides visual language (color, typography style, layout composition, mood) only. Do NOT copy factual claims, text, prices, offers, brand names, or CTAs from the style reference into the output.
```

Place this rule in the HARD RULES section before the creative guidance.

Score the informationPreservation dimension down if style-reference facts contaminate the output.
