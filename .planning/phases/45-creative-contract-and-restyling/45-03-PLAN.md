<objective>
Add a `styleFidelity` criterion to the QA system so that restyling outputs can be flagged when they copy factual claims from the style reference. This is the dedicated check for REST-03 and REST-04 — the existing `creativeRisk` criterion is too vague for style-reference contamination.

Purpose: Without this, restyling QA has no criterion that specifically catches "the output used the wrong brand name from the style reference." The `styleFidelity` criterion provides an explicit pass/warning/failed signal for this.

Output: Updated `creative-qa.ts` with `styleFidelity` in the criterion union and contract-aware `buildCreativeQaPrompt`.
