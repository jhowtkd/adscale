# Plan 141-03 - Conscious Override UX Gap Closure

## Goal

Close the Phase 141 verification gap: blocked creatives must have a conscious override path in the workspace UI, and override-approved package items must not look like normal approvals.

## Why This Plan Exists

`141-VERIFICATION.md` found Phase 141 at `status: gaps_found`, score `3/4`.

The server-side contract is mostly correct:

- `PATCH /api/derivations/[id]/review` accepts `overrideReason`.
- blocked approval without override returns 409.
- short override reason returns 400.
- valid override records `output_decision_events`.
- dual verdict payloads are not rewritten.
- package snapshots expose `approvalOverride`.

The missing piece is the actual workspace UX:

- `DerivationReviewSheet` disables `Entra` for blocked creatives and offers no typed override path.
- `handleReviewDecision` does not accept/pass `overrideReason`.
- `ClientApprovalPackagePanel` renders override-approved items like normal approved items.

## Acceptance Criteria

- Blocked creatives still cannot be approved normally with one click.
- The review sheet offers an explicit secondary override action only when `approvalBlocked` is true.
- Override action requires a typed reason with the same minimum as the API.
- Submitted override calls review mutation with `decision: "entra"` and `overrideReason`.
- The weak `olharVerdict` / `exportStatus` stays visible before, during and after override.
- `ClientApprovalPackagePanel` visibly marks `approvalOverride: true` items and shows the relevant verdict context.
- Focused component/hook tests cover the override UI path and package marker.

## Tasks

**Requirement:** REVIEW-04

- Keep the primary `Entra` button disabled for blocked creatives.
- Add a clearly secondary action such as `Aprovar com override` / `Override approval`.
- Show warning copy that this does not make the creative good; it records an exception.

- Submit:
  - `decision: "entra"`;
  - `overrideReason: overrideReason.trim()`.
- Do not hide `olharVerdict`, `whatBlocks`, or `exportStatus` while override mode is active.
