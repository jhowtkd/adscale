# Plan 141-02 - Override Audit Trail and Package Gating

## Goal

Make blocked creative impossible to approve/package silently. Overrides must be intentional, typed, audited, and must preserve the weak creative verdict.

## Acceptance Criteria

- Review API accepts structured decisions and validates required reasons.
- Normal approval of blocking Olhar/Exportacao verdicts still returns 409.
- Override approval requires typed reason.
- Override creates auditable `output_decision_events` context with actor/campaign/derivation/reason.
- Override does not mutate `olharVerdict` or `exportStatus` into a normal approved-looking verdict.
- Approval/package builders exclude `sem_opiniao`, `confusa`, and `bloqueado` by default.
- Any override-included package item remains visibly marked as override in snapshot/item metadata.

## Tasks

### 141-02-01 - Review API structured decision contract

**Requirements:** REVIEW-03, REVIEW-04

- Extend request schema in `PATCH /api/derivations/[id]/review`.
- Keep legacy `{ status }` accepted for compatibility.
- Require `directionReason` for `nao_entra` and `quase_regenerar`.
- Require `overrideReason` for approving a blocked creative.
- Keep `assertDerivationApprovable` as the default normal approval path.
- Add route tests for:
  - legacy approved still works for approvable derivation;
  - blocked approval without override returns 409;
  - blocked approval with missing/short override reason returns 400;
  - blocked approval with valid override records audit context and keeps verdict payload unchanged.

**Files likely touched:**

- `app/src/app/api/derivations/[id]/review/route.ts`
- `app/src/app/api/derivations/[id]/review/route.test.ts`

### 141-02-02 - Output decision evidence for override and direction reason

**Requirement:** REVIEW-04

- Extend output decision snapshot extras to include:
  - `reason.code`;
  - `reason.text`;
  - `reason.source`;
  - override flag/context if needed.
- Use existing `recordOutputDecisionEvidenceBestEffort`; do not add a separate event table.
- Ensure sensitive media/prompt fields remain excluded by `sanitizeOutputDecisionSnapshot`.
- Add or update tests around output decision snapshot sanitization and route recorder call.

**Files likely touched:**

- `app/src/server/output-learning/output-decision-events.ts`
- `app/src/server/output-learning/output-decision-recorder.ts`
- `app/tests/unit/output-learning/output-decision-event.test.ts`
- `app/src/app/api/derivations/[id]/review/route.test.ts`

### 141-02-03 - Package eligibility and stale reasons use dual verdicts

**Requirements:** REVIEW-01, REVIEW-04

- Extend `DerivationLike` in `client-approval-package.ts` with optional `olharVerdict`, `exportStatus`, and override marker if implemented.
- Add helper such as `isDerivationPackageEligibleByVerdict`.
- Exclude normal package entry when:
  - `olharVerdict.value` is `sem_opiniao`;
  - `olharVerdict.value` is `confusa`;
  - `exportStatus.value` is `bloqueado`.
- Add stale reasons for blocked verdicts, not just unapproved/no-output.
- If override inclusion is supported, expose it explicitly in snapshot items so the UI/export cannot present it as normal approval.

**Files likely touched:**

- `app/src/server/ai/client-approval-package.ts`
- `app/src/server/ai/client-approval-package.test.ts`
- approval package API route/tests if snapshot shape changes
- delivery package route/tests if package generation depends on the same eligibility helper

## Stop Conditions

- Do not bypass `assertDerivationApprovable` without explicit override reason and audit event.
- Do not overwrite weak `olharVerdict`/`exportStatus` to make an override look normal.
- Do not let package selection rely on `status === "approved"` alone.
