# Plan 157-02 - Server-Resolved Workspace Evaluation Boundary

## Goal

Ensure global corpus evaluation writes never trust browser-provided workspace scope. The server must resolve the workspace from the corpus item, preserve scoped compatibility where needed, and keep stale/duplicate evaluation failures explicit.

## Context

Use `.planning/phases/157-global-corpus-access-boundary/157-CONTEXT.md` as the source of truth. The decisive product/security choice is: global evaluation submits `corpusItemId` plus bounded evaluation fields; the server resolves `workspaceId` from the corpus item. If a scoped caller still sends `workspaceId`, the server verifies it matches the item before writing.

## Acceptance Criteria

- Global evaluation route no longer requires `workspaceId` in the request body for platform-owner submissions.
- Evaluation service resolves `workspaceId` from `corpusItemId` before inserting into `human_quality_evaluations`.
- If a scoped request provides `workspaceId`, mismatch with the corpus item fails clearly and does not write an evaluation.
- Pending-state guard remains intact: non-pending item returns conflict and does not corrupt status.
- Non-owner evaluation still returns generic `403 forbidden`.
- Global evaluation action emits lightweight security log with userId, route/action and corpusItemId, without notes/payload/prompts/URLs.
