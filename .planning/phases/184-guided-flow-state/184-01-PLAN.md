# Plan 184-01 - Schema, Types and Repository

## Goal

Add dedicated `assistant_guided_flows` persistence with scoped repository CRUD and safe payload validation.

## Context

Use `.planning/phases/184-guided-flow-state/184-CONTEXT.md`. One flow per thread, JSONB slots/missingFields/assetIds/referenceIds, optional campaignId, reuse PERSISTENCE_DENYLIST.

## Tasks

### 184-01-01 - Add Drizzle schema and migration

**Requirements:** FLOW-01, FLOW-02

<task>
Create migration `0058_assistant_guided_flow.sql` and add `assistantGuidedFlows` table to schema.ts.

Columns: id, workspace_id, client_profile_id, thread_id (unique), path (text), status (text), current_step (text), slots (jsonb), missing_fields (jsonb), asset_ids (jsonb), reference_ids (jsonb), campaign_id (nullable uuid), created_at, updated_at.

FKs: workspace, client_profile, thread (cascade), campaign (set null). Index on workspace_id and thread_id.
</task>

### 184-01-02 - Implement guided-flow repository

**Requirements:** FLOW-01, FLOW-02, FLOW-03, FLOW-04

<task>
Create `app/src/server/repositories/guided-flow.ts` with:

- Types: `GuidedFlowPath`, `GuidedFlowStatus`, `GuidedFlowRecord`, `UpsertGuidedFlowInput`, `PatchGuidedFlowInput`
- `GuidedFlowValidationError` class
- `getGuidedFlowByThread(workspaceId, threadId)`
- `upsertGuidedFlow(workspaceId, threadId, clientProfileId, input)` — create or update
- `patchGuidedFlow(workspaceId, threadId, clientProfileId, patch)` — validate scope, shallow-merge slots, reject denied keys
- Validate thread exists and clientProfileId matches thread on every write
- Reject cross-scope mutations when flow row workspace/client/thread mismatch
</task>
