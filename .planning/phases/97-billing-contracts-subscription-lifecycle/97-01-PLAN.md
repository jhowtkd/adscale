# Plan 97-01: Billing Contracts and Subscription Lifecycle

## Objective

Make subscription status and monthly credit grants authoritative and idempotent before conversion UI depends on them.

## Must Haves

- `/api/billing/status` returns normalized subscription status plus the existing access contract.
- `invoice.paid` grants credits once using `invoice.id` as the ledger source ID.
- `checkout.session.completed` links Stripe entities without granting credits.
- Existing beta access remains independent from paid subscription records.

## Tasks

### Task 1: Normalize billing status

Update `server/billing/access.ts`, `repositories/billing.ts`, and `api/billing/status` types/tests so `trialing`, `active`, `past_due`, `canceled`, and `none` remain observable even when access is denied or falls back to beta.

### Task 2: Harden Stripe lifecycle processing

Audit `server/billing/events.ts` and credit repositories. Enforce `invoice.id` idempotency for grants and keep checkout completion limited to customer/subscription synchronization.

### Task 3: Verify contracts

Add focused event, repository, access, and route tests for duplicate delivery, replay, missing metadata, and beta/paid coexistence.

## Verification

- `npm test -- src/server/billing/events.test.ts src/server/billing/access.test.ts src/app/api/billing/status/route.test.ts`
- No duplicate credit transaction is created when the same invoice event is processed twice.
