# Plan 139-02: Deterministic Export Validator and Approval Blocking

## Purpose

Create the second pass: export validation that decides whether an output can be approved/exported independently from whether it has good art direction.

## Scope

In scope:

- Export validator module.
- CTA normalization table.
- Setup mismatch classification.
- Review route blocking for blocked export status.
- Tests for `approved + invalid` prevention.

Out of scope:

- UI display of export details (Phase 141).
- Typed override reason and event log (Phase 141).
- Real Cenbrap calibration report (Phase 142).

## Tasks

### 139-02-01: Implement deterministic export validator

Implement `export-validation.ts` with:

- `normalizeExportCtaText(text)`.
- issue codes for brand/source identity, CTA drift, offer/claim drift, required text readability, format ratio, resolution and setup mismatch.
- `validateExportReadiness(input)` returning `ExportStatusPayload`.
- deterministic severity:
  - `bloqueado` for wrong brand/source, unsupported offer/claim, setup mismatch, invalid ratio/resolution that prevents delivery, unreadable required text.
  - `ajuste_menor` for normalized CTA punctuation/spacing differences and minor non-blocking copy cleanup.
  - `ok` when no issues.

Acceptance:

- NBSP, repeated whitespace, typographic quotes, hyphen variants and punctuation-only CTA changes normalize before drift decisions.
- Campaign setup mismatch is a `setupIssue`, not an art-direction block.
- Export validator does not emit `sem_opiniao` or `confusa`; those belong to Olhar.

Automated:

`cd app && npm test -- src/server/ai/export-validation.test.ts src/server/ai/export-validation-cta.test.ts`

### 139-02-02: Wire approval blocking to export status

Update approval path so:

- approving a derivation with `exportStatus.value === "bloqueado"` returns 409.
- response details include `qualityVerdict`, `hardFailures`, `olharVerdict`, `exportStatus`.
- old hard-failure behavior remains intact.
- rejected status still does not require export validation.

Acceptance:

- Route test proves `approved + export bloqueado` cannot be created.
- Route test proves `approved + olhar confusa` cannot be created.
- Route test proves rejection still bypasses approvability gate.
- Existing output-decision evidence recording still runs after valid approval/rejection.

Automated:

`cd app && npm test -- src/app/api/derivations/[id]/review/route.test.ts`
