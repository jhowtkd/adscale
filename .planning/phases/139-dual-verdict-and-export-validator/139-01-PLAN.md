# Plan 139-01: Dual-Verdict Contracts and Persistence Compatibility

## Purpose

Make derivations capable of carrying `olharVerdict` and `exportStatus` independently without breaking legacy quality gate behavior.

## Scope

In scope:

- Typed dual-verdict domain module.
- Axis validation for `figura`, `gestalt`, `voz`, `convite` scores 0-3.
- Nullable persistence fields in `derivations`.
- Repository helper for updating dual verdict payloads.
- `assertDerivationApprovable()` compatibility rules.

Out of scope:

- Full export validation logic (Plan 139-02).
- Advisor prompt rewrite (Phase 140).
- Review UI and override UX (Phase 141).

## Files

Create:

- `app/src/server/ai/olhar/dual-verdict.ts`
- `app/src/server/ai/olhar/dual-verdict.test.ts`
- Drizzle migration for nullable `olhar_verdict` and `export_status` jsonb columns.

Modify:

- `app/src/server/db/schema.ts`
- `app/src/server/repositories/derivation.ts`
- `app/src/server/repositories/derivation.test.ts`
- `app/src/server/ai/creative-quality-gate.ts`
- `app/src/server/ai/creative-quality-gate.test.ts`

## Tasks

### 139-01-01: Create dual verdict domain contract

Implement `dual-verdict.ts` with:

- `OlharVerdictValue = "pronta" | "quase" | "sem_opiniao" | "confusa"`.
- `ExportStatusValue = "ok" | "ajuste_menor" | "bloqueado"`.
- `OlharAxisScores` with all four axes scored 0-3.
- payload types for `OlharVerdictPayload` and `ExportStatusPayload`.
- validators/normalizers that reject malformed payloads.
- helper that builds an `olharVerdict` from existing hard failures using Phase 138 `resolveArtDirectionVerdictFromFailures()`.

Acceptance:

- Visual hard failures produce `sem_opiniao` or `confusa`.
- No art-direction hard failures can fall back to `quase` or `pronta` using conservative rules.
- Axis scores outside 0-3 are rejected.
- Payloads require direction text and `evaluatedAt`.

Automated:

`cd app && npm test -- src/server/ai/olhar/dual-verdict.test.ts`

### 139-01-02: Add nullable persistence and repository helper

Add nullable `jsonb` columns:

- `olhar_verdict`
- `export_status`

Expose schema fields:

- `olharVerdict`
- `exportStatus`

Add repository helper:

- `updateDerivationDualVerdict(id, workspaceId, data)`

Acceptance:

- Existing derivation create/update code does not require dual verdict values.
- Repository test proves helper writes both payloads and updates `updatedAt`.
- Types are imported from `dual-verdict.ts`, not duplicated.

Automated:

`cd app && npm test -- src/server/repositories/derivation.test.ts`

### 139-01-03: Make approvability dual-verdict aware

Update `assertDerivationApprovable()` so:

- `olharVerdict.value` of `sem_opiniao` or `confusa` blocks approval.
- `exportStatus.value` of `bloqueado` blocks approval.
- Legacy `qualityVerdict === "invalid"` or hard failures still block approval.
- Missing dual verdict values do not bypass legacy hard failures.
- Rejection response can include dual verdict details when present.

Acceptance:

- `completed` is not enough to approve.
- `qualityVerdict: "improvable"` is still approvable only when dual verdict/export status do not block.
- Legacy rows without dual verdict keep current behavior.

Automated:

`cd app && npm test -- src/server/ai/creative-quality-gate.test.ts src/server/ai/olhar/dual-verdict.test.ts`
