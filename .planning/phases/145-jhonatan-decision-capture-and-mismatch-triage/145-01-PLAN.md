# Plan 145-01 - Operator Decision Capture Workflow

## Goal

Capture Jhonatan's `entra`, `quase`, and `nao_entra` decisions for the current `review_ready` calibration rows in a canonical, replayable way.

## Acceptance Criteria

- The two `review_ready` rows from the contact sheet are enumerated with campaign, derivation id, system verdicts and source label.
- Jhonatan can provide one decision per row: `entra`, `quase` or `nao_entra`.
- Each decision records reviewer and reviewedAt.
- Decisions are persisted in `output_decision_events` or normalized into a calibration artifact that can be consumed deterministically.
- Event snapshots include sanitized `olharVerdict`, `exportStatus`, reason code/text and source label context.
- Duplicate decisions are prevented or clearly superseded by idempotency key/latest-event behavior.
- No prompt text, signed URL, `DATABASE_URL` or raw secret payload is written to planning artifacts.

## Tasks

**Requirements:** JUDGE-01

### 145-01-02 - Canonical event recording path

**Requirements:** JUDGE-02

- Prefer adding `app/scripts/record-cenbrap-calibration-decisions.ts` to apply decisions from JSON.
