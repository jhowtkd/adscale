# Plan 99-01: In-Product Conversion Surfaces

## Objective

Convert spend and entitlement blocks into localized trial or upgrade actions while preserving the user's workspace and campaign context.

## Must Haves

- All billing-related 402 responses share a typed payload with `reason` and an actionable destination or suggested plan.
- Preview and batch gates render CTAs from the server contract rather than inferring from error strings.
- Exhausted beta users can start checkout without losing their current campaign.
- Progression and credit activation upgrade moments route to checkout or Billing settings.

## Tasks

### Task 1: Define the conversion error contract

Extend `server/billing/gates.ts` and API consumers with one structured 402 schema. Migrate spend routes and preserve analytics fields.

### Task 2: Wire preview and batch gates

Update campaign derivation surfaces and billing hooks to show trial/upgrade actions for insufficient credits, exhausted beta access, and subscription recovery states.

### Task 3: Connect existing value moments

Replace inert or generic upgrade actions in progression missions and credit activation components with checkout/Billing navigation that retains return context.

### Task 4: Add focused UI/API coverage

Test payload shape, localized CTA selection, beta exhaustion, and navigation from preview, batch, and progression surfaces.

## Verification

- Focused billing gate, campaign flow, hook, and progression tests pass.
- No billing 402 surface is left with a dead-end message.
