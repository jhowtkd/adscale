# Plan 143-02 - Dual-Verdict Coverage Cleanup and Blocker Classification

## Goal

Make the live calibration result actionable by separating reviewable rows from missing evidence, then route each blocker to the right next step.

## Acceptance Criteria

- Every row without `olharVerdict` or `exportStatus` is counted as missing evidence.
- Missing dual-verdict rows are classified by cause when possible: `missing_olhar`, `missing_export`, `missing_both`, `legacy_derivation`, `no_output_key`.
- The contact sheet tells Phase 144 which rows are reviewable and which rows need regeneration/QA first.
- `143-BLOCKERS.md` exists when Phase 144 should not start yet.
- If enough rows are reviewable, `143-LIVE-RUN.md` explicitly marks Phase 144 as ready for Jhonatan decision capture.

## Tasks

### 143-02-01 - Dual-verdict coverage analysis

**Requirements:** CENLIVE-04

- Parse the live calibration JSON and count:
  - total campaign sections;
  - total derivation rows;
  - rows with both `olharVerdict` and `exportStatus`;
  - rows missing only `olharVerdict`;
  - rows missing only `exportStatus`;
  - rows missing both;
  - rows without safe output refs.
- Record counts in `143-LIVE-RUN.md`.
- If the existing JSON shape does not expose enough detail, add a small inspection helper or document the limitation as `artifact_shape_gap`.
