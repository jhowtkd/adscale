## BUG #1 — Chain-of-thought vazado no chat do assistente
**Severidade:** 🔴 crítica | **Status:** confirmed

**Root cause (confirmed):** O leak é **persist-time E render-time**. No `app/src/server/assistant/orchestrator.ts` (`runAssistantTurn`), o `assistantText` acumulado do stream é persistido cru em `createAssistantMessage({ content: assistantText })` (linha 144). O sanitizer `app/src/server/assistant/model/reasoning-sanitizer.ts` (`stripReasoningFromDelta`) só remove **chaves estruturais** de reasoning (`reasoning_content`, `thinking`, etc.) do delta — ele **não** faz strip de blocos `...` inline dentro de `content`. O `assertNoReasoningInText` (linha 142) só检测a as *chaves* serializadas, não o markup `...`. No render, `app/src/components/assistant/AssistantMessageList.tsx` (`MessageBubble`, linha 59) faz `{message.content}` — texto puro, sem markdown, sem filtro de `...`. O adapter MiniMax (`minimax-adapter.ts:52`) envia `extra_body: { thinking: { type: "disabled" } }`, mas claramente o modelo ainda devolve thinking inline em algum caminho (provável mudança de model ou feature flag).

**Files to change:**
- `app/src/server/assistant/orchestrator.ts` — `runAssistantTurn`, antes de `createAssistantMessage` (linha 144): aplicar `assistantText = stripThinkBlocks(assistantText)`.
- `app/src/server/assistant/model/reasoning-sanitizer.ts` — adicionar `stripThinkBlocks(text: string): string` com regex `/[\s\S]*?<\/think>/g` → `""` (e também `^...$/gm` sem fechamento, para streams truncados).
- `app/src/components/assistant/AssistantMessageList.tsx` — `MessageBubble` (linha 59): render defensivo que ignora/stripa `...` mesmo se vier do banco histórico.
- `app/src/server/assistant/orchestrator.ts` — backfill: rota/migration que limpa mensagens assistant já persistidas com `...`.

**Fix approach:**
- Backend strip antes de persistir (primary fix) — regex `...` → `""`.
- Render defensivo no `MessageBubble` (secondary fix) — garante que histórico já sujo não vaze.
- Adicionar `stripThinkBlocks` ao `reasoning-sanitizer.ts` com testes para: bloco fechado, bloco truncado, múltiplos blocos, sem bloco.
- Snapshot test: nenhuma mensagem assistant persistida contém substring ``.

**Effort estimate:** S (≈0.5d) — regex + 2 pontos de aplicação + teste. Backfill de histórico é M separado.

**Dependencies / blockers:** nenhum. Faz primeiro.

**Acceptance check:** teste unitário em `reasoning-sanitizer.test.ts` asserta `stripThinkBlocks("oi ... segredo ... tchau") === "oi  tchau"`; teste de integracão em `chat/route.test.ts` asserta que `assistantMessage.content` persistido não contém ``.

## BUG #2 — Chave i18n crua `errors.brandKitAmbiguous` no Brand Kit
**Severidade:** 🔴 crítica | **Status:** confirmed (root cause mais preciso que o relatório)

**Root cause (confirmed):** Triplo problema, todos confirmados em código:
1. **Backend** `app/src/app/api/workspace/brand-kit/route.ts` (`GET`, linha 63): `apiError("brandKitAmbiguous", 409, { detail: "Multiple client profiles exist..." })`.
2. **`apiError`** `app/src/lib/api-response.ts` (linha 12-20): chama `t(code)` via `getTranslations("errors")`. Se a chave existe, devolve a tradução; se **não** existe, next-intl **não throws** — invoca `onError` (silent em prod, ver `app/src/i18n.ts:36-46`) e devolve o **fallback** `getMessageFallback` (linha 47-49) que retorna `${namespace}.${key}` = `"errors.brandKitAmbiguous"`. É exatamente o que o banner mostra.
3. **Chave ausente:** `errors.brandKitAmbiguous` **NÃO existe** em `app/messages/pt-BR.json` nem em `app/messages/en.json` (confirmado via script — ambas as catalogs têm `errors.generic`, `errors.internalError`, etc., mas **nenhum** `brandKitAmbiguous`). O `code` `clientProfileNotFound` também não tem tradução.
4. **Frontend** `app/src/components/settings/BrandKitTab.tsx` (linha 412): render `{error?.message || tc("error")}` — mostra direto o `error` do payload (que é a string `errors.brandKitAmbiguous`). `app/src/lib/hooks/use-brand-kit.ts` (`fetchBrandKit`, linha 40) faz `throw new Error(err.error)` — propaga o cru.

**Files to change:**
- `app/messages/pt-BR.json` + `app/messages/en.json` — adicionar `errors.brandKitAmbiguous` (e `errors.clientProfileNotFound`) em ambos.
- `app/src/app/api/workspace/brand-kit/route.ts` — shape do 409: `{ code: "workspace_ambiguous", message: <descritivo>, details: { availableWorkspaces: [...] } }` em vez de `apiError("brandKitAmbiguous", ...)`.
- `app/src/lib/api-response.ts` — `apiError` deveria usar `code` (não `message`) como campo estável e expor `message` traduzido separadamente; fallback para `errors.generic` quando chave falta.
- `app/src/lib/hooks/use-brand-kit.ts` — `fetchBrandKit`: ler `err.message` (não `err.error`) e/ou mapear `code` → ação (abrir seletor de workspace).
- `app/src/components/settings/BrandKitTab.tsx` — banner: render `t(errors.<code>)` com fallback `t("errors.unknown")`; se code for `workspace_ambiguous`, mostrar CTA "Selecionar workspace".

**Fix approach:**
- **Quick fix (1h):** adicionar as 2 chaves faltantes em pt-BR + en. Isto já elimina o vazamento cru.
- **Fix real:** mudar `apiError` para nunca vazar namespace cru — fallback `errors.generic` quando `t(code)` retorna o path.
- **UX:** o 409 significa "conta com múltiplos workspaces/profiles" — adicionar seletor no onboarding/settings; o banner vira CTA.
- **Observability:** logar 409s no Sentry (já existe `captureException` em `handleApiError`, mas `apiError` direto não loga).

**Effort estimate:** S (0.5d) para quick fix de chaves; M (1.5d) para reshape do erro + seletor de workspace.

**Dependencies / blockers:** a UX de seletor de workspace é uma feature separada (tocada também por #8). O quick fix de chaves não tem blocker.

**Acceptance check:** em pt-BR, banner Brand Kit mostra "Sua conta tem múltiplos perfis de cliente. Selecione um para continuar." (não `errors.brandKitAmbiguous`); em EN, mostra a tradução correspondente. Teste: chamar `GET /api/workspace/brand-kit` em workspace com >1 profile e assertar que `body.error` é string traduzida, não `errors.*`.

- Adicionar `setCurrentPageTitle` calls nas pages `/assistant`, `/campaigns`, `/settings` (ou eliminar o pattern em favor de derivação de rota).

**Fix approach:**
