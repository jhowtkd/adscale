Mas tem **3 bugs críticos** que vazam prompt interno, chave de tradução crua e breadcrumb fixo — qualquer um deles quebra a confiança de quem chega pelo link público.

Prioridades na ordem certa:

1. **Crítico** — vazamento de chain-of-thought no chat (`<think>...</think>` aparece no balão da IA)

3. **Crítico** — header mostra "Dashboard" fixo em todas as rotas exceto `/campaigns/[id]`
4. **Alto** — i18n EN quebrado em ~30% das strings (Ç vaza, portunhol "quality corpus", header "DerivAÇÕES")
5. **Alto** — dados de demo vazam ("Teste", "wqee", "Cenbrap")
6. **Médio** — 39 notificações "Derivação pronta" idênticas (boy who cried wolf)
7. **Médio** — light mode dilui a personalidade "studio at 2am"

## Bugs críticos

### BUG #1 — Chain-of-thought vazado no chat do assistente
**Severidade:** 🔴 crítica (segurança/confiança/produto)
**Repro:** `/assistant` → clicar na thread `wqee` (ou qualquer thread) → ler a primeira resposta da IA
**Evidência:** `/tmp/adscale-35-chat-thread-leak.png`

A mensagem da IA começa literalmente com:

> `Quero criar 5 variacoes para Meta Ads publico maes 25-45`
> ` `
> `<think>The user wants to create 5 variations for Meta Ads targeting mothers aged 25-45. The client profile is "Teste" but there's no industry, product, or specific campaign details. I need to ask a clarifying question since the intent is unclear — I don't know what product/service to advertise. **According to my instructions, when intent is unclear, I should ask one clarifying question**: quick action vs. complete campaign, but in this case, I also need basic info about what the ad is for.`
> ` `
> `Let me ask a clarifying question to get the essential info needed to create the variations.</think>`
> ` `
> `Ótimo! Para criar as 5 variações de forma assertiva...`

**Por que é crítico:**
- Expõe o **system prompt** do modelo (literalmente "According to my instructions…")
- Expõe a **heurística interna** do agente ("when intent is unclear, I should ask one clarifying question")
- Faz a UI parecer **debug-mode** ou **staging** — usuário real pensa que está olhando um preview não-pronto
- Marca "Curator > operator" da ADScale se contradiz: o curador mostra o raciocínio cru, perde autoridade

**Root cause provável:** o `<think>...</think>` é um token de raciocínio de reasoning model (DeepSeek-R1, Qwen-QwQ, Claude extended thinking, etc.). O **renderer do chat não filtra** esse bloco antes de inserir no DOM. Provavelmente está sendo gravado no banco como conteúdo da mensagem e re-renderizado em cada load.

**Fix sugerido:**
1. **Backend** — strip do `response` antes de persistir: regex `/<think>[\s\S]*?<\/think>/g` → `""`. Ou configurar o modelo para retornar thinking num campo separado (`reasoning_content`) que vai pro log mas não pro `content`.
2. **Frontend** — defensiva: o renderer do markdown/texto deve ignorar blocos `<think>` mesmo se vierem crus
3. **Teste** — adicionar um snapshot test que garante que NENHUMA resposta de IA contenha `<think>` visível

### BUG #2 — Chave i18n crua `errors.brandKitAmbiguous` no Brand Kit
**Severidade:** 🔴 crítica (profissionalismo/UX)
**Repro:** Configurações → aba "Brand Kit"
**Evidência:** `/tmp/adscale-32-brand-kit-bug.png`, `/tmp/adscale-33-settings-reload.png` (100% reprodutível após reload)

Banner vermelho com texto literal `errors.brandKitAmbiguous`. Sem tradução, sem fallback, sem dica do que fazer.

**Root cause — CONFIRMADO via network capture:**

`GET /api/workspace/brand-kit` retorna **HTTP 409 Conflict** com body:

```json
{
  "error": "errors.brandKitAmbiguous",
  "code": "brandKitAmbiguous",
  "details": {
    "detail": "Multiple client profiles exist; clientProfileId is required"
  }
}
```

São **3 problemas compostos**, não 1:

1. **Backend** — está expondo **chave i18n como mensagem de erro**. O campo `error` deveria ser descritivo em PT/EN, ou só carregar o code (`brandKitAmbiguous`). A chave i18n é interna.
2. **Frontend** — não tem tradução para `errors.brandKitAmbiguous` no `messages/pt-BR.json` (e provavelmente nem em en). Sem fallback, a chave vaza.
3. **UX** — o problema real ("user pertence a múltiplos workspaces, precisa escolher um") está enterrado em `details.detail` que **nunca chega ao usuário**. Quem está vendo o banner não tem como saber o que fazer.

**Fix sugerido (em ordem):**
1. **Resolver o problema real primeiro** — se um usuário tem múltiplos workspaces, o onboarding/UX precisa de um seletor de workspace logo no login. Ou então a API deveria inferir o workspace primário e só exigir `clientProfileId` em casos raros.
2. **Backend** — mudar shape do erro 409:
   ```json
   {
     "code": "workspace_ambiguous",
     "message": "Sua conta tem múltiplos workspaces. Selecione um para continuar.",
     "details": { "availableWorkspaces": [...] }
   }
   ```
3. **Frontend** — renderizar a `message` no banner (não a `code`). Adicionar fallback `t('errors.unknown')` quando chave não existir.
4. **i18n** — adicionar `errors.brandKitAmbiguous` em **pt-BR, en, es** antes do próximo deploy
5. **Observability** — logar esses 409 no Sentry/Datadog pra acompanhar frequência

### BUG #3 — Header mostra "Dashboard" em todas as rotas (exceto detalhe de campanha)
**Severidade:** 🔴 crítica (navegação/confiança)
**Repro:** qualquer rota que não seja `/campaigns/[id]`
**Evidência:** `/tmp/adscale-27-assistant-empty.png` (header diz "Dashboard" mas URL é `/assistant`)

Comparativo:

| URL | Header diz | Deveria dizer |
|---|---|---|
| `/assistant` | "Dashboard" | "Assistente" ou "Chat" |
| `/` | "Dashboard" ✅ | "Dashboard" |
| `/campaigns` | "Dashboard" ❌ | "Campanhas" |
| `/settings` | "Dashboard" ❌ | "Configurações" |
| `/campaigns/[id]` | "Cenbrap NR1" ✅ | "Cenbrap NR1" |

**Root cause:** parece que o header tem um fallback literal `"Dashboard"` quando o breadcrumb dinâmico não computa. Provavelmente o componente lê `useBreadcrumb()` ou similar, e quando não há rota mapeada, cai num default hard-coded em vez de omitir ou mostrar o slug da rota.

**Fix sugerido:**
1. **Mapeamento de breadcrumb** — adicionar todas as rotas (`/assistant` → "Assistente", `/campaigns` → "Campanhas", `/settings/[tab]` → "Configurações · [Tab]", `/campaigns/[id]` → nome da campanha)
2. **Fallback melhor** — se não houver mapeamento, mostrar o último segmento da URL capitalizado em vez de "Dashboard"
3. **Validação** — snapshot test que percorre cada rota e checa que `header.breadcrumb === esperado`

### BUG #6 — Saturação de notificações (39 itens idênticos)
**Severidade:** 🟠 alta (engajamento)
**Evidência:** `/tmp/adscale-28-notifications.png`

Ao abrir o sino: **39 notificações**, todas "Derivação pronta", todas com texto idêntico "Uma derivação da campanha 'Cenbrap em Dobro - Teste' foi gerada com sucesso", datadas de "4 days ago" e "5 days ago".

**Por que importa:**
- Boy who cried wolf — usuário aprende a ignorar notificações porque são ruído
- Itens idênticos deveriam ser **agrupados** ("3 novas derivações em 'Cenbrap em Dobro - Teste'")
- Sem indicador de prioridade/severidade
- Sem CTA clicável (cada item parece passivo)

**Fix sugerido:**
1. **Grouping** — notificações do mesmo tipo+campaign+período viram uma linha
2. **Tipos diversos** — "Variação aprovada pelo cliente", "Comentário em variação", "Briefing precisa de atenção" — dar ao usuário razões diferentes pra abrir
3. **Marcar como lida em massa** — funciona (botão verde), mas o count não atualiza? (validar)
4. **CTA** — tornar cada item linkável à entidade referenciada (campanha, variação)

## Observações positivas (PRESERVAR)

Não mexer no que está bom:

1. **Design system dark mode** — accent verde neon (`#00e85e`→`#3fff80`), tipografia consistente, hierarquia clara
2. **Vocabulário de marca** — "missões", "trilha", "laboratório", "prontidão", "curador", "cientista" — alinhado com a tese "Curator > operator"
3. **Prontidão Criativa com 6 critérios** — feature diferenciadora que ninguém no mercado tem (Clareza, Legibilidade, Hierarquia, CTA, Aderência à marca, Aderência à plataforma). Cada critério scoreado individualmente permite ação corretiva
4. **Gamificação** — "Estrategista", "10/11 missões", progress bar 91% — funciona bem pra onboarding de usuário novo
5. **Painel detalhe da campanha** — denso, útil, bem estruturado. Mostra briefing, perfil do cliente, derivações grid, scoring, ações
6. **Modal Feedback** — política de privacidade explícita ("Capturamos rota, workspace e diagnósticos sanitizados. Capturas de tela e replay de sessão não são coletados") — boa prática
7. **Dropdown de notificações** — pelo menos existe, tem "Marcar todas como lidas" e "Limpar"
8. **System de aprovação/rejeição** — botões "Aprovar" / "Rejeitar" no detalhe da variação
9. **Multi-formato support** — Feed 1:1, Story 9:16, Card 4:5 — relevante pro mercado de ads
10. **Empty states com copy útil** — "Selecione uma thread para ver prontidão do contrato e status de jobs." (painel direito vazio do /assistant)
