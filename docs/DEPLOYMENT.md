# Deployment

How ADScale is built, deployed, and operated in production. The primary path is **Render** via the root Blueprint (`render.yaml`) using Render's **Node.js runtime** (not the Docker image). **Docker** remains available for local development or optional self-hosted production. Environment variables and validation rules are documented in [CONFIGURATION.md](./CONFIGURATION.md).

## Deployment targets

| Target | Config | Runtime | Database | Role |
|--------|--------|---------|----------|------|
| **Render (production)** | `render.yaml` | Node.js web service (`runtime: node`) | Managed PostgreSQL 16 (`adscale-postgres`) | Primary production host |
| **Docker (local / self-hosted)** | `app/Dockerfile`, `app/docker-compose.yml` | Node 20 Alpine, Next.js `standalone` | Postgres 16 container or external URL | Local stack; optional self-hosted production |
| **GitHub Actions** | `.github/workflows/ci.yml` | `ubuntu-latest`, Node 20 | Ephemeral Postgres 16 service | CI only — no deploy job |

There is **no separate Render worker service** in this repository. Background jobs run through **Inngest Cloud**, which calls back into the web service at `/api/inngest`.

### Docker

- **Image:** multi-stage `app/Dockerfile` (`node:20-alpine`), non-root user `nextjs`, port `3000`, `CMD` runs `docker/entrypoint.sh`.
- **Entrypoint:** waits for `postgres:5432`, runs `npx drizzle-kit migrate`, starts `node server.js`.
- **Compose:** `app/docker-compose.yml` — `postgres` + `app`; optional `inngest` dev profile (`--profile dev`). Details: `app/DOCKER.md`.
- **Health check (Compose):** `wget` against `http://localhost:3000/` (not `/api/health`).

Production Docker requires an external database and Inngest Cloud credentials; the bundled Compose file targets local development. Render production does **not** use this Dockerfile.

## Build pipeline

### CI (GitHub Actions)

Workflow: `.github/workflows/ci.yml` (`name: CI`).

**Triggers:** push to `main`, pull requests to `main`.

**Job `test`** (`ubuntu-latest`, Postgres 16 service: `adscale_test` / `test:test@localhost:5432`):

1. Checkout
2. Node.js 20 with npm cache (`app/package-lock.json`)
3. `cd app && npm ci`
4. `npm run lint`
5. `npm run typecheck`
6. `npm run convergence:test && npm run convergence:gate` (freeze manifest on main; no `PRIMARY_DESTINATIONS_ALLOW_BOOTSTRAP`)
7. `npx drizzle-kit migrate`
8. `npm test -- --run`
9. `npm run build` (mock env vars for Zod/build — see workflow file)
10. Start app for e2e (`npm run start &` against the CI Postgres, `NODE_ENV=production`, `E2E_CONTROLLED_PROVIDER=true`, shared `E2E_STORAGE_DIR`)
11. `npx playwright install --with-deps chromium`
12. `npx playwright test tests/e2e/visual-a11y-gate.spec.ts` (blocking)
13. Start Inngest CLI (`inngest-cli dev` targeting `/api/inngest`) and `npm run seed:create-post-e2e`
14. `npx playwright test tests/e2e/critical-studio-journey.spec.ts --project=serial-flows` (create → reload → complete → edit → export, plus partial failure and brand isolation, with deterministic doubles)

There is **no deploy or release job** in CI. Render publishes `adscale-app` and `adscale-image-worker` only when GitHub checks on that SHA pass (`autoDeployTrigger: checksPass`). The evidence is the `test` job on workflow `CI`.

### Render deploy sequence

On each deploy to `adscale-app`:

1. **Build** (in `app/`): `npm ci --include=dev && npm run build && npm prune --omit=dev`
   - Dev dependencies are available for build-time typechecking (including the dev-only accessibility probe) and pruned before the standalone runtime is deployed.
   - `next build --webpack` with `output: 'standalone'` in `app/next.config.ts`
   - `postbuild`: `node scripts/prepare-standalone.mjs` copies `.next/static` and `public/` into the standalone output
2. **Start:** `npm run db:migrate && npm run start:prod`
   - Migrations via `app/scripts/migrate-with-retry.mjs` (retries controlled by `DB_MIGRATE_ATTEMPTS` / `DB_MIGRATE_DELAY_MS`)
   - App boot via `app/scripts/start-with-inngest-sync.mjs`: prepares standalone assets if present, starts Next.js (standalone `server.js` when available), then syncs Inngest functions through `PUT /api/inngest` using `INNGEST_SERVE_URL` or `APP_URL` / `BETTER_AUTH_URL`
   - Render injects `PORT`; the app must listen on `0.0.0.0:$PORT` for the health check to pass

Migrations run at process start, not in a separate `preDeployCommand`. Each new instance applies pending migrations before accepting traffic.

### Stripe production go-live

Before accepting live payments on Render:

1. **Live API keys:** set `STRIPE_SECRET_KEY` to a `sk_live_` or `rk_live_` restricted key in the Render Dashboard.
2. **Live Price IDs:** set `STRIPE_STARTER_PRICE_ID`, `STRIPE_GROWTH_PRICE_ID`, and `STRIPE_SCALE_PRICE_ID` to recurring monthly `price_` IDs from the Stripe Dashboard (live mode).
3. **Webhook endpoint:** in the Stripe Dashboard (live mode), create a webhook pointing at `POST https://adscale.jhonatansoares.com/api/billing/webhook` and copy the signing secret into `STRIPE_WEBHOOK_SECRET` (`whsec_…`). The handler is `app/src/app/api/billing/webhook/route.ts`.
4. **Required webhook events** (enforced by `app/scripts/preflight-stripe-billing.ts`):
   - `checkout.session.completed`
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `invoice.paid`
   - `invoice.payment_failed`
5. **Billing portal:** ensure at least one Customer Portal configuration exists in the Stripe Dashboard (required for `POST /api/billing/portal`).
6. **Preflight check:** from Render Shell or locally with production env loaded:

```bash
cd app
npm run preflight:stripe
# offline schema-only check:
npm run preflight:stripe -- --offline
```

The preflight script validates env vars, URL origins, price IDs (live API mode), and portal configuration without printing full secrets.

### Pre-deploy checklist

- All `sync: false` secrets set in Render.
- Migration SQL committed under `app/drizzle/`.
- `BETTER_AUTH_URL` and `APP_URL` match how users reach the app.
- `MARKETING_URL` and `MARKETING_ALLOWED_ORIGINS` match the public site setup; the `PUBLIC_STUDIO_*` flags hold their approved values.
- Stripe live keys, live Price IDs, and webhook endpoint registered in the Stripe Dashboard (live mode).
- `npm run preflight:stripe` passes against production env.
- Inngest dashboard points at the production `/api/inngest` URL.
- CI green on `main` (lint, typecheck, tests, build).

## Rollback procedure

### Render (application)

1. **Revert and redeploy:** `git revert <commit>` and push to `main` — Render auto-deploys the revert.
2. **Manual deploy:** Render Dashboard → service `adscale-app` → deploy a specific earlier commit.

<!-- VERIFY: Rollback features and deploy history retention depend on your Render plan tier -->

### Database

Drizzle Kit does not ship automatic down-migrations. Options:

1. **Forward fix:** add a new migration that reverses the schema change, then deploy (migrations run in `startCommand` via `npm run db:migrate`).
2. **Restore backup:** restore Postgres from Render backup or a manual `pg_dump` before re-deploying app code.

<!-- VERIFY: Free Render Postgres may not include automated backups; confirm backup policy before production cutover -->
